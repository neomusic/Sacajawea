# Sacajawea

[![npm version](https://badge.fury.io/js/%40neomusic%2Fsacajawea.svg)](https://badge.fury.io/js/%40neomusic%2Fsacajawea)

## SEO-correct multi-locale routing for Next.js App Router

Next.js App Router has no native routing i18n (unlike Pages Router, which does). Sacajawea fills that
gap without replacing App Router's own `[locale]` segment + middleware pattern: it gives you pretty,
per-locale URLs (`/it/notizie`, `/en/news`) that all resolve to one internal route, plus the hreflang,
canonical and sitemap wiring that pretty multi-locale URLs need to be indexed correctly.

If you're on Pages Router, use its [native i18n routing](https://nextjs.org/docs/pages/building-your-application/routing/internationalization)
instead — you don't need this package there.

> Coming from v2 (`@palmabit/sacajawea`)? See the
> [migration guide](https://github.com/neomusic/Sacajawea/wiki/Migration-v2-to-v3) on the wiki. v3 is a
> different package (`@neomusic/sacajawea`) with a different architecture, not a drop-in upgrade.

## Install

```
npm install @neomusic/sacajawea
npx sacajawea init
```

`init` detects `app/` and scaffolds `sacajawea.config.ts`, `app/[locale]/layout.tsx`, `app/[locale]/page.tsx`
and `proxy.ts` (or `middleware.ts` on Next <16 — rename the generated file if you're not on 16+).

## Define your routes

```ts
// sacajawea.config.ts
import { defineRoutes } from '@neomusic/sacajawea'

export default defineRoutes({
  defaultLocale: 'it',
  locales: ['it', 'en'],
  siteUrl: 'https://example.com',
  routes: {
    home: { it: '/', en: '/' },
    newsDetail: { it: '/notizie/[slug]', en: '/news/[slug]' }
  }
})
```

Every route needs a pattern for every locale. Internally, every route lives once under the
**default locale's** pattern shape (`app/[locale]/notizie/[slug]/page.tsx` in the example above); the
proxy rewrites every other locale's pretty URL onto that same file. `npx sacajawea add-route <name>`
scaffolds this for you — it asks for a slug per locale and creates the page at the right path.

## Link and useLocale

```tsx
// lib/navigation.ts
import { createNavigation } from '@neomusic/sacajawea/client'
import config from '../sacajawea.config'

export const { Link, useLocale } = createNavigation(config)
```

```tsx
<Link route="newsDetail" locale="en" params={{ slug: 'hello' }}>News</Link>
```

`useLocale()` reads the current locale from the `[locale]` route segment. Without a `route` prop,
`<Link>` behaves like plain `next/link`.

## Metadata, sitemap and proxy

```ts
// lib/seo.ts
import { createAppHelpers } from '@neomusic/sacajawea/app'
import config from '../sacajawea.config'

export const { alternatesMetadata, buildSitemap, generateLocaleParams, createProxy } = createAppHelpers(config)
```

```tsx
// app/[locale]/notizie/[slug]/page.tsx
export async function generateMetadata({ params }: { params: Promise<{ locale: string }> }) {
  const { locale } = await params
  return { alternates: alternatesMetadata({ route: 'newsDetail', locale, params: { slug: 'hello' } }) }
}
```

```ts
// app/sitemap.ts
export default function sitemap() {
  return [buildSitemap({ route: 'home' }), buildSitemap({ route: 'newsDetail', params: { slug: 'hello' } })]
}
```

`createProxy`/`createMiddleware` return the same function under both names — it's a plain
`{ redirect?, rewrite? }` descriptor, not a `NextResponse`, so `proxy.ts` (generated by `sacajawea init`)
adapts it:

```ts
// proxy.ts
import { NextResponse, type NextRequest } from 'next/server'
import { createAppHelpers } from '@neomusic/sacajawea/app'
import routesConfig from './sacajawea.config'

const { createProxy } = createAppHelpers(routesConfig)

export default function proxy(request: NextRequest) {
  const result = createProxy(request)
  if (result.redirect) return NextResponse.redirect(new URL(result.redirect, request.url))
  if (result.rewrite) return NextResponse.rewrite(new URL(result.rewrite, request.url))
  return NextResponse.next()
}

export const config = { matcher: ['/((?!_next|api|.*\\..*).*)'] }
```

## Scope of this release

Built and verified against a real Next 16 App Router project: redirect on `/`, pretty-URL rewrite,
`generateStaticParams`, and real `canonical`/`hreflang`/`x-default` output.

Not in this release (planned as follow-ups): Pages Router adapter, `<LocaleSwitcher>`,
`sacajawea doctor` (SEO lint), JSON-LD helpers, a v2→v3 config codemod.
